# AI-assisted customer builds

Admin dashboard -> Open request & AI build -> review request -> confirm data sharing -> Generate AI Website Brief.
Only this explicit authenticated action calls OpenAI. Business name, industry, website and project description are sent; dedicated contact fields are excluded. Free-text descriptions may still contain personal data, so review them first.

The Responses API uses strict structured output, server-side validation, a 60-second timeout, no automatic retries, and store=false. This flag does not promise zero provider retention. Default model: gpt-4.1-mini; optional server override WEBFACTORY_AI_MODEL.

Review the draft JSON, missing information and proposed copy. Regenerate while in draft; old versions remain in private PostgreSQL history. Approve for Build freezes the selected version. Copy the Codex Build Prompt and give it to Codex manually.

No files are generated by the workflow. No email/SMS is sent. No customer site is published or deployed. Preview-ready requires the expected customer URL and an explicit manual verification acknowledgement. Customer-approved requires the preceding preview-ready stage and acknowledgement that actual customer approval was obtained.

Codex must inspect the existing customer schema, confirm the slug is unused, create isolated assets/routes, preserve other customers, verify facts, retain noindex and disabled integrations, generate delivery artifacts, and run all checks. Deployment and DNS require separate authorization.

## Storage and security

- Run npm run webfactory:migrate before deploying; migration 0003 adds only webfactory.ai_briefs, build_workflows and build_events.
- Every endpoint checks admin session and same origin. Briefs have no public route.
- Generation is globally limited to six admin attempts per 15 minutes using shared PostgreSQL counters.
- A durable running-generation record prevents overlapping generation/approval. Runs abandoned for three minutes can be replaced manually.
- Brief IDs must match the selected request/version. Approved requests cannot regenerate.
- Audit records contain generation status, IDs, timestamps and safe failure codes, not credentials/provider error bodies.
- Legacy generic status updates cannot bypass build approvals.
- OPENAI_API_KEY is server-only. Missing key displays AI generation unavailable.
- Existing email-disabled and manual-payment gates remain unchanged.

## Deployment

Set OPENAI_API_KEY as a production secret on the existing Vercel project. Optionally set WEBFACTORY_AI_MODEL. Apply migration; run npm run lint, npm run build, node scripts/test-ai-brief.mjs and admin workflow checks. Commit/push to the verified existing repository and deploy with the existing Vercel project link.

For each future generated customer: approval -> manual Codex build -> QA -> separately approved deployment -> record verified preview URL -> actual customer approval. Marking a workflow status does not perform any of these external actions.

Implementation reference: https://developers.openai.com/api/docs/guides/structured-outputs
